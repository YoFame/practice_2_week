## 3. Журнал Спринта 3

### План спринта
**Цель дня:** реализовать создание занятия и отметку статуса посещаемости для каждого студента.

**Роли:** Кузнецов Дмитрий — PO, Лазарев Антон — LD, Гунченко Василиса — QA/DevOps.

**Задачи по ролям:**
- PO (Кузнецов Дмитрий): описать сценарий занятия (выбор группы и даты, статусы «Присутствовал», «Отсутствовал», «Опоздал»); определить правило одной итоговой отметки на студента и занятие.
- LD (Лазарев Антон): создать модель `Attendance` и `Lesson`; экран занятия и экран отметки посещаемости; реализовать сохранение выбранных статусов с помощью RadioGroup; предусмотреть изменение статуса до сохранения.
- QA (Гунченко Василиса): подготовить тест-кейсы для всех статусов, пустого списка, повторной отметки и изменения статуса; проверить отображение списка из нескольких студентов.

### Результат спринта
- Экран занятия и список студентов с выбором статуса.
- Модель данных `Attendance` и `Lesson`.
- Сохранение отметок в текущем сеансе (в памяти).
- Реализована живая статистика посещаемости.
- Тестовые сценарии для проверки статусов.

### Definition of Done — статус
- [x] Преподаватель может выбрать занятие и отметить каждого студента.
- [x] Статусы различаются (Присутствовал, Отсутствовал, Опоздал).
- [x] Изменение статуса работает до нажатия кнопки «Сохранить».
- [x] Пустой список обрабатывается понятным сообщением.
