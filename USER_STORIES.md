# Требования к проекту: Система контроля посещаемости

## Проблема
Преподаватель ведёт несколько учебных групп с большим числом студентов. Учёт посещаемости ведётся вручную, поэтому:
- Медленно открывать нужную группу на занятии.
- Нет быстрого способа увидеть, сколько студентов присутствовало на занятии.
- Процент посещения для отчётности считается вручную.
- Чтобы понять, что студент пропустил, приходится листать записи.

## Описание экранов

### Главное меню
- **Назначение:** точка входа, навигация по основным разделам.
- **На экране:** название приложения, кнопки: «Студенты», «Отметка посещаемости», «Статистика».
- **Действия:** переход в любой из трёх разделов.

### Студенты
- **Назначение:** ведение учебных групп и списков студентов.
- **На экране:** список учебных групп, внутри группы — список студентов (ФИО); кнопки: добавить группу, редактировать, удалить.
- **Действия:** создать/переименовать/удалить группу; добавить/редактировать/удалить студента (ФИО + группа); открыть карточку студента.

### Отметка посещаемости
- **Назначение:** создание занятия и отметка статусов студентов.
- **На экране:** выбор занятия (учебная группа + дата + тема), список студентов выбранной группы, у каждого переключатель статуса (присутствовал, отсутствовал, опоздал), поле комментария (необязательно), статистика, кнопка «Сохранить».
- **Действия:** создать занятие, отметить статус каждому студенту, добавить комментарий, сохранить отметки.

### Статистика
- **Назначение:** отчётность по посещаемости.
- **На экране:** выбор объекта (группа или студент), выбор периода (по умолчанию текущий месяц), сводка по группе, список студентов, отсортированный по числу пропусков, история по студенту.
- **Действия:** переключить группу/студента, выбрать период, просмотреть сводку и историю.

# СПРИНТ 2: Студенты и учебные группы (в процессе)

**Цель:** реализовать добавление, просмотр и удаление студентов с проверкой введённых данных.

## Уточнение полей и правила валидации
**Сущность «Студент»:**
- **ID** (обязательное поле, создается автоматически).
- **Фамилия** (обязательное поле, только буквы, без пробелов в начале/конце).
- **Имя** (обязательное поле, только буквы, без пробелов в начале/конце).
- **Учебная группа** (обязательное поле, студент не может существовать без группы).

**Сообщения об ошибках (для разработчика и QA):**
- Если поля пустые: *«Ошибка: поле не может быть пустым»*.
- Если введены только пробелы: *«Ошибка: поле не может быть пустым»*.
- При успешном добавлении: *«Студент [Фамилия Имя] успешно добавлен»*.

## Новые User Stories (Спринт 2)

| User Story | Критерии приёмки |
|---|---|
| **US-2.1.** Как преподаватель, я хочу добавлять новых студентов в список, чтобы вести учет. | 1. Форма добавления содержит поля: Фамилия, Имя, Группа.<br>2. Кнопка «Добавить» активна.<br>3. После нажатия данные сохраняются.<br>4. Новый студент сразу появляется в общем списке. |
| **US-2.2.** Как преподаватель, я не хочу, чтобы приложение ломалось из-за моих ошибок при вводе. | 1. Если поля пустые, выдается сообщение об ошибке.<br>2. Если введены только пробелы, выдается сообщение об ошибке.<br>3. Приложение не вылетает (не крашится) при неверном вводе. |
| **US-2.3.** Как преподаватель, я хочу удалять студентов из списка (например, если они отчислились). | 1. В списке студентов есть кнопка/иконка «Удалить».<br>2. Перед удалением появляется диалоговое окно «Вы уверены?».<br>3. После подтверждения студент исчезает из списка. |
